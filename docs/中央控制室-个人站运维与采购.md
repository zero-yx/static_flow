# zero-yx 个人站 · 运维与采购

Windows 本机的日常阅读入口是 <http://127.0.0.1:39080/>；健康检查是 <http://127.0.0.1:39080/healthz>。浏览器直接访问即可。该地址不能给外部读者访问。

## 本机到底运行了什么

源码来自 [zero-yx/static_flow 的 personal/site-build](https://github.com/zero-yx/static_flow/tree/personal/site-build)，部署基线为 `a3516e8`；Windows 适配保存在独立本地分支 `local/win-control-room`。使用实际编译的 Yew/WASM 首页、文章页、归档和本分支的 [2026 GitHub Wrapped](http://127.0.0.1:39080/standalone/github-wrapped-2026.html)。中国大陆某些网络可能无法加载前端使用的第三方字体、公式或代码高亮 CDN，上线前要用目标读者网络复查。

本机的 Python 服务只读公开构建目录和 `content/site-notes`，按前端协议提供文章、分类、标签、关键词搜索，不调用模型、不写库。它不是完整的 Axum/LanceDB 后端；AI 审核、评论、语义检索、音乐上传、公共模型网关、后台管理均没有对外服务。个人站健康与 Codex、Magpie 或 DSH 模型是否在线无关。不要把工作台、个人浏览器登录、Codex 订阅和这个站一起暴露到公网。

## 发布一篇笔记

1. 在 `content/site-notes/` 下放一对同名文件，如 `first-project.json` 与 `first-project.md`。文件名用小写英文、数字、短横线。JSON 参考 `site-guide.json`：标题、摘要、日期、分类、标签。正文用 Markdown。只把打算展示给读者的资料放进这个目录。
2. 本机重新载入 `/posts/first-project`，并从 `/posts`、搜索各走一遍。内容变更会在下一次请求读取；无需重新编译整个站。
3. 在本地 Git 记录。通过中央控制室的站点场景记录本次提交、可预览的页面路径、验收结果和回退提交。公开发布另行操作。

## 启动、构建和恢复

在 Windows 仓库根运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-local-site.ps1`。启动器只监听 IPv4 回环，站点已经在线则复用；日志在 `.local/site-stderr.log`，不会被提交。Windows 重启后需重新启动，或者从中央控制室的站点入口使用同一启动命令。私有数据、运行日志和二进制不应放进 Git。

前端源码变更应先提交。再进入本机 WSL 的仓库目录，用当前分支要求的 Rust 工具链、wasm32 目标、Trunk 0.21.14 及 Node/npm 执行：

```bash
export PATH="$HOME/.nvm/versions/node/v24.11.1/bin:$HOME/.cargo/bin:$PATH"
bash scripts/build-local-site.sh
```

脚本用当前本地提交导出独立源码副本，按仓库部署工作流裁剪仅前端的 workspace，以 `STATICFLOW_API_BASE=/api` 构建；不修改开发 checkout 的 Cargo 清单。它保留旧的 `.local/site-previous.*`，构建失败不替换正在使用的站。Git 可恢复源码，但不能恢复尚未备份的运行数据。恢复时先停本服务，保留故障版，把一个经过核验的旧构建目录恢复为 `.local/site`，重新启动并检查首页、文章、Wrapped 和健康端点。

完整自托管的官方方法见 [个人 fork 的部署说明](personal-fork-deploy.zh.md)。该路线还需要固定 Git 子模块和 Rust 工具链、合适的 protobuf/LLVM 等构建依赖，以及内容、评论、音乐三个数据根。生产环境应使用受限服务用户、反向代理和严格的管理面隔离，而不是把本机开发服务器直接对外开放。

## 采购清单：按阶段购买

下表为容量起步建议和人民币预算量级，不是供应商报价。流量、地区、域名后缀、续费与备份都会影响账单；付款前看续费价和流量超额价。

| 项目 | 个人文章站上线 | 什么时候升级 |
|---|---|---|
| 域名和 DNS | 非必须。先用托管商子域名；需要固定品牌再注册一个域名（常见约 ¥50–150/年）。DNS 和 TLS 可用免费方案。 | 面向中国内地且部署在内地节点时，购买前先向接入商核对备案条件。 |
| 主机 | **推荐起步：Linux x86_64、1–2 vCPU、2 GB RAM、30–40 GB SSD**，预编译前端后上传；轻量 VPS 常见预算 ¥30–100/月。用反向代理 443 和只读内容 API。 | 若选 Pages，只适合纯静态文件；当前文章 API 必须另配同源 API/函数或先实现静态导出。只上传 dist 不等价于完整本站。 |
| 完整 Axum/LanceDB | 当前不必买。若要开文章评论、数据库搜索、媒体库，可先从 **4 vCPU、8 GB RAM、80 GB SSD** 的运行实例测量，再按数据量扩容。构建单独在本机或 16–32 GB RAM 的构建机。 | 对代表性数据量测高峰内存、查询延迟和并发；大规模向量、媒体转码、模型任务应分开评估。 |
| 流量和 CDN | WASM、字体、图片由浏览器下载。开启 gzip/Brotli，对带哈希的 WASM/JS 长缓存，HTML 短缓存。试运营月流量从 50–100 GB 估，按访问统计调整。 | 先按 5000 次冷加载 × 压缩后的实测 MB 估算月流量；音视频另计。CDN 不是本机运行的前提。 |
| 异地备份 | 至少保留另一地点的一份 Git 源码与站点笔记；有运行数据后另配加密对象存储，预算可先按 20–50 GB。每周抽样恢复。 | 音乐、图片原件与数据库快照增大后，按月新增 GB、保留期、下载费重算。无需预购托管数据库。 |
| 运维与邮件 | SSH 密钥、免费证书续期、外部 HTTPS 健康探测、预算告警。站点评论/邮件未启用，不急着买 SMTP 或 AI 额度。 | 有注册、邮件通知、内容审核需求时再分别配置。 |

首轮上线验收：通过公网域名访问 443，首页能加载 WASM、文章直链刷新不丢、年度回顾能打开、测试写请求被拒、管理/API Key 不公开；从异地备份恢复一篇文章并复核。不要仅凭首页 HTTP 200 就切换正式 DNS。
